1. FORMULASI MASALAH
Input: data apa yang dibutuhkan?: Daftar riwayat transaksi acak berbentuk larik objek (ID_Transaksi, Waktu, Nominal, Status) dan satu string target_id yang dicari.
Output: apa yang dihasilkan sistem?: Daftar transaksi yang terurut menaik (ascending) berdasarkan ID_Transaksi, detail transaksi yang ditemukan (atau None), serta metrik jumlah perbandingan (comparisons) dan waktu eksekusi (runtime).
Objective: masalah apa yang diselesaikan?: Mengurutkan riwayat transaksi secara stabil sekaligus mempercepat pencarian ID_Transaksi secara berulang dibandingkan pencarian sekuensial.
Constraints dan asumsi: Setiap ID_Transaksi bersifat unik, seluruh data muat di memori (RAM), dan pengujian dibatasi pada data sintetis berskala n = 100, 1.000, hingga 10.000 baris.
Definisikan V, E, dan n pada dataset: Proyek ini memodelkan data secara tabular/sekuensial dengan ukuran masukan n (jumlah baris transaksi), sehingga tidak menggunakan simpul (V) dan sisi (E) karena fokusnya adalah pengurutan dan pencarian indeks, bukan penelusuran relasi antarakun.
Aturan atau indikator yang ingin diperiksa: Pencocokan eksak (==) pada ID_Transaksi setelah normalisasi spasi dan huruf kapital (.strip().upper()).
Gambarkan atau jelaskan representasi adjacency list untuk graph berarah: Menggunakan List of Dictionaries di Python ([{"id": "TRX-01", "waktu": "...", "nominal": 20000, "status": "SUCCESS"}, ...]) agar pengaksesan atribut tetap O(1) dan mudah diurutkan berdasarkan kunci id.
Jelaskan mengapa sebuah akun yang terhubung belum tentu terlibat fraud: Transaksi berstatus PENDING atau jam berdekatan umumnya disebabkan jeda sinkronisasi jaringan QRIS kasir, sehingga temuan sistem hanya menjadi indikator verifikasi kasir, bukan bukti kecurangan.

2. PEMILIHAN ALGORITMA DAN JUSTIFIKASI
s2-bfs: Tidak dipilih. Proyek kami memodelkan riwayat transaksi kasir QRIS sebagai daftar catatan sekuensial (list of objects) untuk pencarian ID transaksi, bukan jaringan graf (graph) antarakun, sehingga penelusuran hop transfer tidak dibutuhkan.
s2-dfs: Tidak dipilih. Fokus studi kasus kami adalah mengurutkan riwayat mutasi dan mempercepat pencarian ID_Transaksi yang bersifat unik, bukan mendeteksi siklus aliran dana atau ketergantungan antar-simpul pada graf berarah.
s2-sort: Dipilih. Digunakan untuk merapikan riwayat transaksi QRIS yang masuk secara acak menjadi terurut menaik (ascending) berdasarkan ID_Transaksi agar memudahkan audit harian pemilik usaha sekaligus menjadi prasyarat wajib sebelum pencarian cepat dilakukan.
s2-search: Dipilih. Binary Search dipilih sebagai solusi utama untuk melacak ID_Transaksi secara berulang pada data terurut dalam waktu {O}(\log n), sedangkan Linear Search dipilih sebagai baseline pembanding untuk mengukur selisih efisiensi langkah pada data acak.
Bandingkan BFS vs DFS: struktur data, output, keterbatasan, dan kompleksitas: BFS menggunakan antrean (Queue / FIFO), sedangkan DFS menggunakan tumpukan (Stack / LIFO atau rekursi). Output: BFS menghasilkan urutan penelusuran melebar per tingkat (level-order) yang menjamin jalur terpendek (minimum hops) pada graf tak berbobot, sedangkan DFS menghasilkan penelusuran mendalam ke satu cabang hingga ujung yang efektif untuk mendeteksi siklus (back edge) menggunakan status WHITE/GRAY/BLACK. Keterbatasan: BFS membutuhkan memori lebih besar saat graf sangat lebar, sedangkan DFS tidak menjamin jalur terpendek dan berisiko stack overflow pada graf sangat dalam; selain itu, keduanya tidak relevan diterapkan pada proyek QRIS kami yang datanya berbentuk tabel linier (array), bukan graf. Kompleksitas: Keduanya memiliki kompleksitas waktu {O}(V + E) dan kompleksitas ruang {O}(V).
Tentukan algoritma Sorting yang dipakai dan alasan pemilihannya: Algoritma sorting yang dipilih adalah Merge Sort (berbasis paradigma Divide and Conquer). Alasannya: (1) memiliki kompleksitas waktu yang terjamin stabil pada {O}(n \log n) baik pada kondisi best case, average case, maupun worst case, jauh lebih efisien dibandingkan Bubble Sort atau Insertion Sort yang ber kompleksitas {O}(n^2) saat menangani hingga n = 10.000 baris transaksi; (2) bersifat stable sort sehingga urutan relatif transaksi yang memiliki kunci setara tetap terjaga; dan (3) mampu menyiapkan struktur data terurut secara konsisten untuk dieksekusi oleh Binary Search.
Jelaskan mengapa hasil ketiga algoritma tidak otomatis membuktikan fraud: Algoritma komputasi (Sorting, Searching, maupun penelusuran graf) hanya mengolah pola struktural, urutan indeks, dan kesesuaian atribut data secara matematis, bukan memvalidasi konteks kejadian nyata di lapangan. Dalam studi kasus transaksi QRIS UMKM kami, transaksi yang berstatus PENDING, nominal identik, atau waktu berdekatan umumnya terjadi akibat kendala sinkronisasi jaringan internet atau keterlambatan rekapitulasi manual kasir. Oleh karena itu, keluaran algoritma hanya berfungsi sebagai indikator awal untuk mempermudah verifikasi dan audit, bukan bukti mutlak terjadinya tindak kecurangan (fraud).

Pseudocode DFS deteksi siklus: ALGORITHM BinarySearch(arr_sorted, target_id)
  low <- 0
  high <- length(arr_sorted) - 1
  steps <- 0
  WHILE low <= high DO
    steps <- steps + 1
    mid <- (low + high) // 2
    IF arr_sorted[mid].id == target_id THEN
      RETURN arr_sorted[mid], steps
    ELSE IF arr_sorted[mid].id < target_id THEN
      low <- mid + 1
    ELSE
      high <- mid - 1
  RETURN None, steps

def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i]['id'] <= right[j]['id']:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:]); result.extend(right[j:])
    return result

def linear_search(arr, target_id):
    target = target_id.strip().upper()
    steps = 0
    for item in arr:
        steps += 1
        if item['id'].strip().upper() == target:
            return item, steps
    return None, steps

def binary_search(arr_sorted, target_id):
    if not arr_sorted or not target_id:
        return None, 0
    target = target_id.strip().upper()
    low, high, steps = 0, len(arr_sorted) - 1, 0
    while low <= high:
        steps += 1
        mid = (low + high) // 2
        curr = arr_sorted[mid]['id'].strip().upper()
        if curr == target:
            return arr_sorted[mid], steps
        elif curr < target:
            low = mid + 1
        else:
            high = mid - 1
    return None, steps
Jelaskan fungsi tiap blok dan variabel state penting: left/right menyimpan sub-larik rekursif pada merge_sort; low, high, dan mid membatasi indeks ruang pencarian pada binary_search; steps menghitung jumlah perbandingan operasi.
Catat output aktual setelah kode dijalankan: Untuk 500x pencarian berulang pada n = 10.000, Linear Search membutuhkan 2.443.232 langkah (0,9685 detik), sedangkan Merge Sort + Binary Search hanya membutuhkan 6.195 langkah (0,1052 detik).

Gejala pada graph bersiklus: Program mengalami perulangan tanpa henti (infinite loop) saat dijalankan pada graph yang memiliki siklus seperti B -> D -> E -> B. Proses tidak pernah selesai, tidak mengembalikan output, dan konsumsi memori terus meningkat hingga program hang.
Root cause pada kode: Variabel visited sudah dibuat di awal fungsi, tetapi tidak pernah digunakan untuk mencatat node yang telah dikunjungi (tidak ada perintah visited.add) dan tidak ada pengecekan sebelum memasukkan tetangga ke antrean (if neighbor not in visited). Akibatnya, node di dalam siklus terus dimasukkan kembali ke queue secara berulang-ulang.
Perbaikan kode dan alasannya: from collections import deque

def reachable_fixed(graph, start):
if start not in graph:
return set()
visited = {start}
queue = deque([start])
while queue:
node = queue.popleft()
for neighbor in graph[node]:
if neighbor not in visited:
visited.add(neighbor)
queue.append(neighbor)
return visited

Alasan: Mencatat node ke dalam visited tepat saat dimasukkan ke queue mencegah node yang sama diproses berulang kali saat melewati siklus, serta penggunaan deque membuat operasi pengambilan antrean berjalan efisien.
Regression test setelah perbaikan: Fungsi reachable_fixed diuji kembali menggunakan dataset A-F yang memiliki dua siklus (B-D-E-B dan C-D-E-F-C) dengan start node 'A'. Program langsung berhenti dan mengembalikan {'A', 'B', 'C', 'D', 'E', 'F'} tanpa infinite loop, serta lolos pengujian ulang pada graph tanpa siklus dan start node tidak valid ('Z') dengan status PASS.
